# Что люди называют «крутым сайтом»

Техника без вкуса — демка. Вкус без техники — макет в Figma. Сходятся они на трёх осях.

## 1. Пространственная непрерывность

Объект не телепортируется. Телефон на первом экране — тот же силуэт, что крутится через 2000 px. Это **один персонаж**, не набор баннеров. Apple держит это жёстко: цвет, масштаб, камера.

Приём: одна сцена (canvas/WebGL/video), несколько «глав» скролла меняют параметры сцены, DOM-текст приезжает поверх.

## 2. Время, подчинённое жесту

Пользователь крутит колесо — мир отвечает *пропорционально*, не «запустил 800ms ease-out и игнорит скролл». Это scrub: `progress = map(scroll, start, end, 0, 1)`.

Scroll-jacking (мы перехватываем wheel и сами анимируем) даёт «премиальность» и ломает доступность, скроллбар, якоря, мобильный инерционный скролл. Apple на продуктовых страницах чаще **растягивает документ** (`height: 500vh`) и пиннит сцену через sticky/свой anim system, оставляя нативный скролл источником времени.

## 3. Материал

«Дорого» = правильный свет, motion blur в самом ролике (не в CSS), зерно, отражения. Это почти всегда **заранее снятый ролик или пререндер**, а не realtime shader. Realtime нужен, когда пользователь крутит продукт (viewer). Повествование «чип внутри корпуса» дешевле и красивее как видео.

Поэтому Apple смешивает:

- пререндер webm, привязанный к вьюпорту (play/pause/load/unload);
- 3D viewer (lotus + USDZ), когда нужен контроль пользователя;
- тысячи `picture/srcset` для статичных кадров (на `/iphone` — 215 `<picture>`, без video).

## Антипаттерны «крутости»

| Выглядит дорого | Обычно значит |
| --- | --- |
| Smooth scroll на всём сайте | конфликт со скроллбаром, accessibility |
| Custom cursor | лаг 1 кадр, бесит на трекпаде |
| Split text каждой буквы | 200 DOM-нод, INP убит |
| Полноэкранный WebGL фон | батарея, 8% GPU на текст |
| Автоплей звука | закрытая вкладка |

Linear и Stripe часто *сдержаннее* Awwwards SOTD и от этого кажутся взрослее: один фирменный эффект (cloth-gradient / сетка точек), остальное — типографика и воздух.

## Иерархия решений (пока не открыли Three.js)

1. Типографика, сетка, цвет, фото.
2. CSS transition на `transform`/`opacity`.
3. Scroll-driven CSS / sticky.
4. Видео с lifecycle по вьюпорту.
5. Canvas sequence / WebGL только где DOM физически не может.

Эта иерархия — и есть «как пишутся сложные сайты» у команд, которые потом могут это поддерживать.
