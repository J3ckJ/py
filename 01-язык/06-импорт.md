# Импорт: не директива препроцессора, а рантайм-протокол

`import x` — это не «вставить файл». Это поиск, загрузка, выполнение модуля и привязка имени. Language Reference, «The import system». К 3.15 у этого механизма появился языковой `lazy import`; до него все «ленивые импорты» были соглашениями.

## Что происходит при `import pkg.mod`

1. Смотрим `sys.modules['pkg.mod']`. Есть — возвращаем. Импорт **идемпотентен** на уровне кэша, не на уровне «файл не выполнится дважды если вы выкинули кэш».
2. Если нет — ищем **finder** в `sys.meta_path`. По умолчанию: builtin, frozen, PathFinder.
3. Finder возвращает **spec** (`ModuleSpec`: имя, loader, origin, is_package).
4. Создаётся пустой модуль, кладётся в `sys.modules` **до** выполнения (чтобы работали циклические импорты).
5. Loader исполняет код модуля в `module.__dict__`.
6. Имя `pkg.mod` привязывается в текущем namespace.

Циклический импорт «работает», если оба модуля успели положить себя в `sys.modules` и вы обращаетесь только к уже исполненным именам. Если `a` импортирует `b`, а `b` на верхнем уровне читает `a.foo`, которого ещё нет — `AttributeError`. Лечение: импорт внутри функции, или рефакторинг циклов, или в 3.15 — осознанный lazy.

## `from x import y`

Это не отдельный механизм поиска `y` на диске. Это `import x`, затем `getattr(x, y)` (с запасным импортом субмодуля, если `x` — пакет и `y` — субмодуль).

Поэтому `from requests import Session` зависит от того, что `requests/__init__.py` экспортировал `Session`. Реэкспорт в `__init__` — публичный API пакета; звёздочка `from x import *` смотрит `__all__`.

## Пакеты

Каталог с `__init__.py` — regular package. Без него, но с namespace (PEP 420) — namespace package, `__path__` составной. Для приложений почти всегда regular. Для плагинов, размазанных по нескольким дистрибутивам — namespace (`requests` так не делает; `google.*` делает).

Относительный импорт (`from .foo import bar`) работает только внутри пакета и привязан к `__package__`, не к текущей директории. Запуск `python mypkg/mod.py` ломает относительные импорты — запускайте `python -m mypkg.mod`.

## Finders и loaders — точки расширения

pytest assertion rewriting — это `MetaPathFinder` + loader, который **переписывает AST** перед компиляцией. importlib.metadata, zipimport, namespace — тоже finders.

Если вы пишете плагин-систему «найти все модули в папке» — не изобретайте `exec(open())`. Используйте `importlib.import_module` и `pkgutil.walk_packages`, либо entry points (`importlib.metadata.entry_points`).

## Побочные эффекты импорта

Импорт выполняет тело модуля. Поэтому:

- Не создавайте соединения, потоки, временные файлы на верхнем уровне без крайней нужды.
- `if __name__ == "__main__"` защищает скрипт, не библиотеку.
- Циклы, тяжёлые `import numpy` в CLI-утилите, которой нужен только `--help` — главная причина медленного старта.

Python 3.15 (`lazy import json`) создаёт прокси и грузит модуль при первом использовании имени. Это языковая фиксация того, что люди делали через TYPE_CHECKING и импорты внутри функций. Для библиотек: не полагайтесь, что ваш top-level import уже всё инициализировал, если пользователь написал `lazy`.

## `__getattr__` модуля (PEP 562)

Модуль может определить `__getattr__(name)` и `__dir__`. Так делают ленивые реэкспорты без `lazy import`: при `from pkg import Rare` редкий объект создаётся только при доступе. Pydantic и typing этим пользуются.

## Компиляция

`.py` → AST (PEP 617, PEG parser с 3.9) → compiler → code object → опционально `.pyc` в `__pycache__`. `python -O` выкидывает `assert` (и `if __debug__`). Никогда не используйте `assert` для проверки безопасности или входных данных API — в `-O` их не будет. Pydantic/FastAPI валидируют сами; `assert` — для инвариантов разработки.

## Где это в живом коде

- pytest `AssertionRewritingHook` в `sys.meta_path`.
- Django `import_string("django.middleware.csrf.CsrfViewMiddleware")` — импорт как данные конфигурации.
- FastAPI анализирует сигнатуры **уже импортированных** callables; тяжёлые зависимости лучше лениво создавать внутри `Depends`, не на импорте модуля.

См. `examples/07_import_hooks.py`.
