# Что такое Python на самом деле

Python — это не «язык с отступами» и не «медленный язык для скриптов». Это **спецификация поведения объектов** плюс несколько реализаций, из которых доминирует CPython.

## Три разных «Python»

1. **Язык** — то, что описано в Language Reference. `a + b` означает «вызови протокол сложения», а не «сложи машинные слова».
2. **Реализация** — CPython, PyPy, GraalPy, MicroPython. Они обязаны соблюдать язык, но не обязаны иметь GIL, refcount или тот же `id()`.
3. **Экосистема** — PyPI, packaging, научный стек, веб-фреймворки. Большая часть того, что люди называют «программированием на Python», живёт здесь, не в синтаксисе.

Если вы учите только (1) — не сможете прочитать Django. Если только (3) — будете копировать заклинания, пока не взорвётся дескриптор.

## Что Python гарантирует, а что нет

Гарантирует Language Reference:

- У каждого объекта есть **идентичность, тип, значение**.
- Имена — это привязки в пространстве имён, не ячейки памяти «переменной».
- Протоколы (итерация, контекст, дескрипторы, вызываемость) имеют определённую семантику.
- `with`, `async for`, генераторы, исключения — часть языка, не библиотеки.

Не гарантирует (это CPython):

- `id(x)` — адрес в памяти.
- Немедленный вызов `__del__`.
- GIL.
- Что `a = 256; b = 256; a is b` истинно (интернирование маленьких int).

Правило профессионала: **пишите по языку, оптимизируйте по реализации, тестируйте на той реализации, которой продаёте**.

## Дизайн, который не меняется с 1991

Три решения Гвидо, которые до сих пор определяют, как выглядит крупный Python-код:

1. **Всё — объект**, включая типы, функции, модули, классы, код. Метапрограммирование — не надстройка, а нормальный путь.
2. **Протоколы вместо интерфейсов**. «Утиная типизация»: достаточно реализовать `__iter__`, чтобы стать iterable. Позже `typing.Protocol` дал этому статическую форму, но runtime остался утиным.
3. **Явное лучше неявного — кроме контекста**. Zen говорит про явность, но Flask `request` и FastAPI `Depends` существуют, потому что Python даёт *дешёвые* неявные каналы: контекстные переменные, дескрипторы, декораторы. Зрелый код использует их узко и документирует.

## Что изменилось к 2026 году (и почему это важно)

Долгое время «настоящий Python» означал: CPython, GIL, eager imports, аннотации как строки или ложь. Сейчас одновременно верно другое:

| Было «навсегда» | Стало |
| --- | --- |
| GIL обязателен | Free-threaded build официально поддержан в 3.14 (PEP 779), всё ещё не default |
| Аннотации считаются при `def` | 3.14: deferred evaluation (PEP 649/749) |
| Один интерпретатор на процесс | 3.14: `concurrent.interpreters` в stdlib (PEP 734) |
| Импорт = выполнить модуль сейчас | 3.15: `lazy import` (PEP 810) |
| `dict` нельзя заморозить встроенно | 3.15: `frozendict` (PEP 814) |
| «Python медленный, нужен PyPy/C» | Специализирующий интерпретатор, экспериментальный JIT, pydantic-core, Polars, uvloop/anyio |

Это не отменяет модель объектов. Это меняет *цену* решений: потоки снова имеют смысл для CPU, аннотации больше не обязаны быть строками, старт приложения можно делать ленивым языковым средством, а не трюком.
