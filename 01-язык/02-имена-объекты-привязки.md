# Имена, объекты, привязки

Это единственная глава, без которой остальные будут казаться магией.

## Объект

Цитата Language Reference, которую стоит выучить наизусть:

> All data in a Python program is represented by objects or by relations between objects. Even code is represented by objects.

У объекта три свойства:

- **identity** — не меняется. `is` сравнивает её. В CPython `id(x)` — адрес.
- **type** — почти не меняется (присваивание `__class__` — исключение для new-style instances). Тип решает, какие операции допустимы.
- **value** — может меняться, если тип мутабельный.

Мутабельность контейнера — про *набор ссылок*, не про значения внутри. Кортеж из списка «неизменяем» как контейнер: нельзя заменить элемент, но можно сделать `t[0].append(1)`.

## Имя — не коробка

```python
a = [1, 2]
b = a
b.append(3)
# a is b  → True, один список
```

`a` и `b` — имена в namespace, оба указывают на один объект. Присваивание **никогда не копирует объект**. Оно меняет привязку имени.

Отсюда все классические «баги новичков», которые в проде выглядят серьёзнее:

```python
def add(item, bucket=[]):  # один список на все вызовы
    bucket.append(item)
    return bucket
```

Дефолт аргумента создаётся **один раз**, при исполнении `def`, и живёт в `function.__defaults__`. Это не синтаксический сахар, это объект.

Правильно: `bucket=None` и создание списка внутри. Или `bucket: list | None = None`.

## Пространства имён — обычные dict (почти)

Четыре пространства, которые видны в каждом кадре:

1. **locals** — локальные имена функции. В CPython 3.11+ это часто не настоящий `dict`, пока вы не вызовете `locals()` (PEP 667 уточнил семантику `f_locals`).
2. **enclosing** — ячейки замыкания (`__closure__`, `nonlocal`).
3. **globals** — `function.__globals__`, это `__dict__` модуля, где функция *определена*, не где вызвана.
4. **builtins** — `function.__builtins__`.

Поиск имени: LEGB. Присваивание без `global`/`nonlocal` всегда создаёт локальное имя (компилятор решает это статически: любое присваивание в функции делает имя локальным на всю функцию).

```python
x = 1
def f():
    print(x)  # UnboundLocalError, если ниже есть x = ...
    x = 2
```

Это не runtime-сюрприз, это решение компилятора: `x` — локаль, потому что в теле есть присваивание.

## Аргументы — тоже привязки

Вызов `f(x)` привязывает локальное имя параметра к тому же объекту, что и `x`. Поэтому:

```python
def bump(n):
    n += 1        # для int: новое имя n, снаружи ничего
def bump_list(xs):
    xs.append(1)  # мутация объекта, снаружи видно
```

«Передача по значению или по ссылке?» — ложный вопрос. Передаётся **ссылка на объект** (call by object sharing). Мутабельность объекта решает, увидит ли вызывающий эффект.

## Копии, которые люди имеют в виду

| Хотели | Написали | Получили |
| --- | --- | --- |
| Другой список тех же элементов | `b = a` | тот же список |
| Поверхностная копия | `b = a[:]` / `list(a)` / `copy.copy` | новый контейнер, те же элементы |
| Глубокая | `copy.deepcopy` | рекурсивные новые объекты |
| Неизменяемый снимок | `tuple(a)` | новый кортеж ссылок |

В проде чаще нужен не deepcopy, а явная схема: «этот объект принадлежит мне, тот — вызывающему». Pydantic `model_copy(deep=True)` и Django `QuerySet._clone()` — примеры *контролируемого* копирования, не слепого.

## `is` против `==`

- `is` — идентичность. Для синглтонов (`None`, `True`, `False`, `...`) — канонично.
- `==` — `__eq__`. Может быть переопределён, может быть медленным, может бросать.

Сравнение с `None` пишите `x is None`. Сравнение маленьких int через `is` — ошибка, даже если сегодня повезло с intern.

## Где это в живом коде

- Flask `LocalProxy`: имя `request` всегда одно, объект за ним — тот, что лежит в `ContextVar` текущего запроса.
- requests `Session`: cookies/adapters — состояние *сессии-объекта*, не глобали модуля. Модульный `requests.get()` создаёт временную Session и закрывает её.
- SQLAlchemy: `Session.add(obj)` не копирует `obj`, а регистрирует *тот же* Python-объект в identity map.
