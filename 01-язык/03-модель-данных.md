# Модель данных: как синтаксис становится вызовом метода

Почти весь «синтаксический сахар» Python — это вызов dunder-методов. Language Reference, раздел 3.3, — главный документ языка. Ниже — не таблица всех `__foo__`, а **карта протоколов**, которые реально держат экосистему.

## Тип — тоже объект

`type(x)` возвращает объект типа. Для встроенных это `int`, `list`, … Для классов, определённых в Python, это сам класс. Классы создаются вызовом `type(name, bases, namespace)` или метаклассом.

```python
class A: pass
assert A.__class__ is type
assert isinstance(A, type)
```

`type` — метакласс по умолчанию. Pydantic подменяет его на `ModelMetaclass`: тело класса становится *входом компилятора*, не просто словарём атрибутов.

## Протокол объекта (базовый набор)

| Операция | Метод | Заметки |
| --- | --- | --- |
| `repr(x)` | `__repr__` | для отладки, должна быть однозначной |
| `str(x)` | `__str__` | для людей |
| `hash(x)` | `__hash__` | если есть `__eq__` и объект мутабельный — обычно `None` |
| `x == y` | `__eq__` | нет — сравнение идентичности |
| `bool(x)` | `__bool__` иначе `__len__` | пустой контейнер ложен |
| `x.attr` | см. дескрипторы | отдельная глава |
| `x[key]` | `__getitem__` | slices — объект `slice` |
| `len(x)` | `__len__` | обязана быть `>= 0` |
| `iter(x)` | `__iter__` | иначе sequence через `__getitem__` |
| `next(it)` | `__next__` | StopIteration заканчивает |
| `x()` | `__call__` | функции, классы, middleware |
| `with x` | `__enter__`/`__exit__` | `__exit__` получает (exc_type, exc, tb) |

Не реализуйте протокол «наполовину». Объект с `__eq__` без `__hash__` (или с `__hash__ = None`) нельзя класть в `set`/`dict` keys. Объект с `__enter__` без корректного `__exit__` утечёт.

## Числовой протокол и `NotImplemented`

`a + b` пробует `a.__add__(b)`. Если тот вернул `NotImplemented`, пробуется `b.__radd__(a)`. С 3.14 использование `NotImplemented` в булевом контексте — `TypeError` (раньше это молча было истинным). Правильный отказ от операции — **вернуть** `NotImplemented`, не бросать, не возвращать `False`.

## Итераторы против итерируемого

- Iterable: имеет `__iter__`, возвращающий iterator.
- Iterator: имеет `__next__` и `__iter__` (обычно `return self`).

Генератор — iterator, созданный компилятором из функции с `yield`. Он же реализует `close`/`send`/`throw` — это основа `yield from`, `@contextmanager` и (исторически) корутин до `async`.

`for x in xs` ≈

```python
it = iter(xs)
while True:
    try:
        x = next(it)
    except StopIteration:
        break
    ...
```

Исключение как управление потоком здесь — часть языка, не антипаттерн.

## Последовательности и отображения

Sequence: `__getitem__` от `int`, `__len__`. Mapping: `__getitem__` от ключа. `collections.abc` фиксирует это в ABC: если регистрируете свой тип, наследуйте или реализуйте методы ABC, иначе `isinstance(x, Sequence)` солжёт.

С 3.7 `dict` сохраняет порядок вставки — это уже язык, не трюк CPython 3.6.

## Контекстные менеджеры

`with expr as a:`:

1. `mgr = expr`
2. `a = mgr.__enter__()`
3. тело
4. `mgr.__exit__(type, val, tb)` — если вернул истинное значение, исключение подавляется

`contextlib.contextmanager` превращает генератор в менеджер: код до `yield` — enter, после — exit. FastAPI так же оборачивает `yield`-зависимости через `AsyncExitStack`. Один и тот же протокол, разные этажи стека.

## Вызываемые объекты

Классы вызываемы: `Foo()` → `__call__` метакласса (обычно `type.__call__`) → `__new__` → `__init__`. Можно сделать вызываемый экземпляр (`def __call__(self, ...)`). requests-аутентификация — callable: `auth(prepared_request)`. Flask/Django/Starlette-приложение — callable с фиксированной сигнатурой WSGI/ASGI.

Паттерн «объект-стратегия как функция» в Python естественен, потому что `__call__` — протокол, а не особый вид функции.

## Атрибуты: не поле, а поиск

`x.foo` — не «прочитать поле». Алгоритм (упрощённо, см. следующую главу):

1. Тип `type(x)` и его MRO: если там дескриптор данных (`__get__` + `__set__`/`__delete__`) — он побеждает.
2. `__dict__` экземпляра.
3. Дескриптор не-данных (обычные функции → методы).
4. `__getattr__`, если ничего не нашли.

`__getattribute__` — полная замена алгоритма, почти никогда не нужен. `__getattr__` — fallback. Werkzeug `LocalProxy` перехватывает **все** обращения через `__getattribute__` прокси, потому что должен притворяться другим объектом.

## Аннотации — не типы runtime (пока вы их не попросите)

До 3.13 аннотации в `__annotations__` вычислялись при определении функции. С 3.14 они отложены (PEP 649): хранится annotate-функция, `annotationlib.get_annotations` умеет форматы VALUE / FORWARDREF / STRING.

Это важно, потому что FastAPI и Pydantic *читают* аннотации как данные. Отложенность ускоряет импорт и разрешает forward references без кавычек — но ломает код, который делал `def f(x: expensively())` и ждал побочный эффект при `def`. Побочный эффект в аннотации и раньше был плохой идеей; теперь он ещё и не произойдёт.

## Где это в живом коде

- `Response.__call__` в Werkzeug — Response *есть* WSGI-приложение.
- `QuerySet.__iter__` в Django вызывает `_fetch_all()` — итерация = SQL.
- Pydantic `BaseModel.__init__` почти пустой: работа в `SchemaValidator.validate_python`.
