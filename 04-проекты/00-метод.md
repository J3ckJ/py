# Метод разбора проектов

Каждый файл в этой папке — не обзор «как пользоваться», а **вскрытие**: горячий путь, состояние, граница I/O, урок для своего кода.

Исходники не вендорятся. Номера строк — по clone августа 2026, ориентир, не вечная истина. Идите в GitHub на `main` и читайте ту же функцию.

Общий шаблон, который повторяется у всех зрелых библиотек:

1. **Тонкий публичный фасад** (`requests.get`, `httpx.get`, `pytest.main`).
2. **Объект-оркестратор со состоянием** (Session, Client, FastAPI, Session ORM).
3. **Скомпилированный план** (PreparedRequest, Dependant, CoreSchema, middleware chain).
4. **Сменный транспорт** (Adapter, Transport, DB backend, plugin hook).
5. **Протокол ресурса** (close / ExitStack / yield fixture).

Когда пишете свой фреймворк на 200 строк — вам нужен (2) и (4). (3) появляется, когда профилировщик показал, что вы парсите сигнатуры на каждый запрос.
