# Упаковка, инструменты, качество — срез 2026

Экосистема сборки Python долго была болью (`setup.py`, easy_install, virtualenv vs venv, pip vs conda). К 2026 картина стабилизировалась вокруг нескольких инструментов. Это не религия, это снижение энтропии.

## Что ставить в PATH

| Задача | Инструмент, который стоит знать |
| --- | --- |
| Установка Python | официальные installers / uv / deadsnakes / pyenv |
| Венв + запуск | `uv` (очень быстро) или `python -m venv` + pip |
| Зависимости приложения | `pyproject.toml` + lock (`uv.lock` / `pylock.toml` тенденции) |
| Сборка библиотеки | hatchling / setuptools / scikit-build-core (натив) |
| Линт+формат | **Ruff** (заменил black+isort+flake8 у большинства новых репо) |
| Типы | Pyright / basedpyright / mypy |
| Тесты | pytest |
| Безопасность зависимостей | pip-audit / uv audit |

Poetry жив, но новые проекты чаще стартуют на uv+hatchling. Не мигрируйте рабочий Poetry «ради моды».

## `pyproject.toml` — единая точка

PEP 517/518/621: метаданные и сборочный бэкенд. `setup.py` остаётся для сложных нативных случаев. Если вы публикуете библиотеку — `[project]` таблица, `readme`, license, requires-python.

Версии: `~=8.2` vs pin. Приложения пинят (lock). Библиотеки задают диапазоны и тестируют матрицу.

## Колёса и ABI

Wheel — zip с тегом `cp314-cp314-manylinux...`. Free-threaded: `cp314t`. Если вы не поставляете C-код — `py3-none-any.whl`. Если поставляете — cibuildwheel.

Никогда не коммитьте `__pycache__` и `.egg-info`. `src/` layout (как у requests, Flask, pytest) предотвращает случайный импорт из рабочей директории вместо установленного пакета.

## Тесты как часть ремесла

pytest победил unittest в экосистеме, но unittest — stdlib, Django TestCase на нём. Пишите:

- быстрые unit без сети;
- контрактные на границах (httpx mock transport, pytest monkeypatch);
- мало end-to-end.

Assertion rewriting pytest — причина, почему `assert a == b` даёт дифф. Не заменяйте на `self.assertEqual`, если уже на pytest.

Покрытие: `coverage` / `pytest-cov`. 100% — фетиш; покрытие границ и ветвей ошибок важнее.

## Качество без бюрократии

Ruff на CI + pre-commit. Один `ruff format` вместо споров о пробелах. `noqa` — исключение, не стиль.

Типы на публичных API. Внутри можно слабее. `Any` хуже, чем отсутствие аннотации: вы солгали анализатору.

## Документация

Docstrings — для функций, которые вызывают другие люди. Sphinx / MkDocs. OpenAPI у FastAPI — не замена человеческому тексту про инварианты и побочные эффекты.

## Где это в живом коде

Посмотрите `pyproject.toml` у httpx и pydantic: extras (`httpx[http2]`), Python requires, ruff конфиг. Это часть архитектуры поставки, не «обвязка».
