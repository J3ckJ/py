# Синтаксис, который важен в настоящем коде

Синтаксис ради синтаксиса не разбираем. Ниже — конструкции, без которых крупные проекты нечитаемы.

## Comprehensions и генераторные выражения

```python
names = [u.name for u in users if u.active]
unique = {u.id for u in users}
index = {u.id: u for u in users}
total = sum(u.amount for u in users)  # не список в памяти
```

Генераторное выражение в `sum(...)` — ленивое. Список — нет. В Django *не* пишите `[x.id for x in Model.objects.all()]` на больших таблицах — сначала `.values_list("id", flat=True)` или iterator.

Вложенные comprehensions быстро становятся нечитаемыми. Тогда — обычный цикл. PEP 798 (3.15) разрешает unpacking внутри comprehensions: меньше `itertools.chain` в однострочниках.

## Присваивание в выражении (walrus, PEP 572)

```python
if (n := len(items)) > 10:
    ...
```

Уместен, когда иначе двойной расчёт или двойной lookup. Не уместен в каждом `if`.

## Распаковка

`a, *rest, z = seq`, `dict1 | dict2` (PEP 584), `{**d, "x": 1}`. В сигнатурах: `*args: int, **kwargs: str` — это типы для checker, в runtime args это tuple, kwargs dict.

## Декораторы

`@dec` ≈ `f = dec(f)`. С аргументами: `@dec(x)` ≈ `f = dec(x)(f)`. Стековые декораторы применяются снизу вверх.

В проде декоратор почти всегда должен:

1. `@functools.wraps(fn)` — сохранить `__name__`, `__doc__`, сигнатуру для inspect (FastAPI/pytest это едят).
2. Не ломать `isinstance` и методы (для классов — `update_wrapper` осторожно).
3. Решать, sync или async: два wrapper'а или `inspect.iscoroutinefunction`.

Flask `@app.route` не «магия URL», а регистрация в `url_map` + `view_functions`. pytest `@fixture` регистрирует в `FixtureManager`.

## `match` / `case` (PEP 634)

Структурный паттерн-матчинг. Хорош для разбора tagged data (JSON-команды, AST, ASGI `scope["type"]`). Плохой вкус — заменить им все `if`. Захватывающие имена в паттернах легко затеняют переменные — читайте PEP про «мягкие» ключевые слова `match`/`case`.

## Генераторы как протоколы данных

`yield` превращает функцию в фабрику iterator'ов. `yield from` делегирует. `send` / `throw` — корутины PEP 342; сегодня вы почти не пишете их руками, но `contextmanager` и pytest fixtures на них стоят.

`async def` + `await` — отдельный тип (coroutine). Нельзя `await` обычный generator. `asyncio.gather`, TaskGroup (3.11+) — супервизия.

## Аннотации только там, где граница

Публичные функции модулей, модели API, параметры CLI — да. Каждая локальная `i: int` в цикле — шум. Consistency важнее полноты.

## f-строки и t-строки

f-строки (и PEP 701: произвольные выражения вложеннее) — основной способ. Логирование: `logger.info("user %s", id)` всё ещё лучше f-строки, если уровень выключен (ленивость) — хотя в 3.14+ мир цветной REPL это уже не главная боль.

PEP 750 **template strings** (`t"..."`) в 3.14 — не немедленная интерполяция, а объект шаблона для безопасной обработки (SQL/HTML/shell не клеить через f-string). Если строите запросы — это направление, не `f"SELECT {col}"`.

## Менеджмент потока

`for`/`else` существует (else, если не было `break`) — в проде почти не используют, читатели спотыкаются. `while`/`else` — ещё хуже. `for` + флаг яснее.

`with` обязателен для ресурсов. `async with` — для async-ресурсов (httpx.AsyncClient, Session.begin).

## Где это в живом коде

Почти каждый файл Flask/FastAPI — декораторы регистрации. Каждый pytest-тест — фикстуры как DI через имена параметров. Каждый Django ORM-вызов — ленивый объект, который станет SQL при итерации, не при создании.
