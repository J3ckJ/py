# Память, ссылки, сборка циклов

CPython (классическая сборка) уничтожает объект, когда счётчик ссылок доходит до нуля. Циклы (`a.x = b; b.y = a`) refcount не спасает — ими занимается циклический GC (`gc` module).

## Refcount в голове

Каждая привязка имени, элемент контейнера, кадр, который держит локаль — +1. Конец функции, `del`, перепривязка — −1. Это объясняет:

- почему `__del__` может вызваться в случайном месте (в другом потоке — ещё веселее);
- почему файл без `close` иногда «закрывается сам», а на PyPy — нет (другой GC);
- почему циклы с `__del__` — боль: финализаторы и циклы плохо дружат.

Правило: **не пишите `__del__`**. Пишите `close()` + context manager. `__del__` — последний предохранитель для C-ресурсов.

## Циклический GC

Поколения (в 3.14 — incremental GC, меньше пауз). `gc.collect()` принудительно. Объекты с `__del__` в несобираемом цикле попадают в `gc.garbage` (исторически) — не стройте такие циклы.

`sys.getrefcount(x)` всегда на 1 больше, чем вы думаете: аргумент самой функции — ещё одна ссылка. Для отладки утечек: `tracemalloc`, `objgraph`, в 3.14 — улучшенный debugger interface (PEP 768), в 3.15 — Tachyon sampling profiler и frame pointers по умолчанию (PEP 831).

## Слабые ссылки

`weakref.ref(obj)` не держит объект живым. Кеши, реестры слушателей, identity maps побочных индексов. SQLAlchemy identity map держит strong refs на persistent objects — это *намеренно* (Unit of Work должен видеть объект). Не путайте с weak.

## intern, синглтоны, immortal

Маленькие int, некоторые строки, `None`/`True`/`False` — могут быть уникальны. Free-threaded build делает часть констант **immortal**: refcount не трогают, чтобы не было cache-line ping-pong между ядрами. `sys.intern` на 3.14t = бессмертие до shutdown. Не intern'ите произвольный пользовательский ввод.

## Что реально жрёт память в приложениях

Не «overhead объекта 16/32 байта», а:

- гигантские list/dict,
- pandas copies,
- Django QuerySet, вытянутый целиком в `_result_cache`,
- кэш шаблонов + ORM identity map на весь процесс,
- утечка response body в httpx/requests при `stream=True` без чтения.

`QuerySet._fetch_all` делает `list(iterable)` — вот ваш RAM. `.iterator()` / `.aiterator()` — когда строк много.

## Арена аллокаторов

Классический CPython: pymalloc для мелких объектов, системный malloc для крупных. Free-threaded: mimalloc, несколько куч, QSBR. Практический вывод: `gc.collect()` на 3.14t *может* освободить то, что QSBR откладывал; RSS процесса всё равно может не упасть сразу — аллокатор не отдаёт страницы OS.

## Где это в живом коде

- Django `_result_cache` — явная материализация.
- requests `Response.content` кеширует тело; `iter_content` — нет.
- Pydantic: Rust валидатор пишет в `__dict__` модели напрямую, минуя Python `__setattr__` (если не запрещено) — меньше временных объектов.
